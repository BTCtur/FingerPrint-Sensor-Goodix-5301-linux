# Goodix 27c6:5301 Protocol Specification

This document describes the USB protocol and image decoding for the **Goodix `27c6:5301`** fingerprint sensor, found in laptops such as the Dell Inspiron 15 (7577).

---

## 1. Hardware & Interfaces

The sensor enumerates over USB with Vendor ID `0x27C6` and Product ID `0x5301` as a USB Communication Device Class (CDC ACM) modem:

- **Interface 0 (CDC Communication):**
  - Endpoint `0x82` IN (Interrupt, 64 bytes)
- **Interface 1 (CDC Data):**
  - Endpoint `0x03` OUT (Bulk, 64 bytes)
  - Endpoint `0x81` IN (Bulk, 64 bytes)

All driver commands and frame transfers occur over the **bulk endpoints of Interface 1**.

---

## 2. Message Framing ("Wrapless" Protocol)

Messages sent between host and MCU follow Goodix's "wrapless" framing format:

```text
Byte 0:     Command code (e.g. 0x00 for PING, 0x20 for IMAGE)
Bytes 1..2: Payload length + 1 (uint16 little-endian)
Bytes 3..N: Payload
Last byte:  Checksum
```

### Checksum Algorithm
```python
checksum = (0xAA - (sum(message_bytes_except_checksum) & 0xFF)) & 0xFF
```

### Chunking
- Messages are transmitted in 64-byte USB bulk packets.
- The initial chunk begins with the 3-byte header.
- Continuation chunks begin with `cmd | 1`, followed by up to 63 bytes of payload.
- Every packet is padded to 64 bytes with `0x00`.

---

## 3. Command Codes

| Command | Opcode | Description |
|---|---|---|
| `PING` | `0x00` | Liveness check |
| `IMAGE` | `0x20` | Request frame capture |
| `FDT_MANUAL` | `0x36` | Finger detection mode (essential for contrast) |
| `SLEEP` | `0x60` | Put sensor to sleep |
| `CONFIG` | `0x90` | Upload 256-byte sensor RAM configuration |
| `RESET` | `0xA2` | Sensor reset |
| `FIRMWARE` | `0xA8` | Query firmware version |
| `ACK` | `0xB0` | MCU acknowledgment (`payload[0] == cmd`) |
| `DRV_STATE` | `0xC4` | Host driver state notification |

---

## 4. Activation Sequence

1. **DRAIN:** Send PING and drain stale reply packets left in the MCU TX queue.
2. **PING (`0x00`):** Liveness test.
3. **FIRMWARE (`0xA8`):** Verify firmware string (`GF3208_HT_APP_10035` / `GF5288_HT_APP_10035`).
4. **RESET (`0xA2`):** Sensor hardware reset (`[0x01, 20]`).
   - *Note on 5301:* Following the ACK, the MCU sends a stray `0xA2` status message which must be skipped.
5. **CONFIG (`0x90`):** Upload 256-byte configuration to MCU RAM. Returns `0x01` on success.
6. **DRV_STATE (`0xC4`):** State notification sent twice (`[0x01, 0x00]`).
7. **FDT_MANUAL (`0x36`):** Configure finger detection registers.
8. **BACKGROUND (`0x20`):** Capture empty sensor reference frame.
9. **POLL LOOP (`0x20`):** Repeatedly acquire frames and compare against background.

---

## 5. Frame Decoding & Cryptography

- **Sensor Resolution:** 108 × 88 pixels (9,504 pixels).
- **Depth:** 12-bit packed (4 pixels per 6 bytes = 14,256 payload bytes).
- **Packet Structure:** `[5-byte Header] [14,256 bytes Payload] [4-byte CRC32/MPEG-2]`

### 5.1. Integrity Check
The payload is verified using CRC32/MPEG-2 (polynomial `0x04C11DB7`, initial value `0xFFFFFFFF`).

### 5.2. GEA Stream Cipher De-obfuscation
Each 16-bit little-endian word is XORed with a keystream generated by Goodix's GEA cipher initialized with the fixed key `0x12345678`.

### 5.3. 12-bit Pixel Unpacking
For each 6-byte block `c[0..5]`:
- `pixel[0] = ((c[0] & 0x0F) << 8) | c[1]`
- `pixel[1] = (c[3] << 4) | (c[0] >> 4)`
- `pixel[2] = ((c[5] & 0x0F) << 8) | c[2]`
- `pixel[3] = (c[4] << 4) | (c[5] >> 4)`

### 5.4. Image Normalization & Cropping
Edges (2 pixels on each side) are cropped, yielding an effective resolution of **104 × 84 pixels**. The background reference frame is subtracted, and the contrast is stretched to an 8-bit range (`0..255`).

## 6. Biometric Matching: Why SIGFM?

Standard minutiae extractors (such as NBIS / bozorth3) require at least 10–12 genuine minutiae points. Due to the small physical sensor area (5 × 4 mm), NBIS detects only 2–3 minutiae, resulting in a false-rejection rate of nearly 100%.

The driver uses **SIGFM (MR !530)**, which uses OpenCV SIFT keypoints and descriptor matching. On real 5301 hardware, same-finger scores exceed 400 (against a threshold of 40), while different fingers score below 5, providing fast and reliable authentication.
